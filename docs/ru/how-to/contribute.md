# Работа с репозиторием

[English version](../../../CONTRIBUTING.md)

## Настройка рабочей копии

1. Выберите версию Node.js из `.nvmrc`.
2. Выберите версию npm из `package.json`. Её можно установить командой `npm install --global --ignore-scripts npm@12.2.3`.
3. Запустите `npm ci`.
4. Запустите `npm run hooks:install`. Команда задаёт локальный путь хуков Git.
5. Запустите `npm run check` и `npm run audit:deps`.

Хук pre-commit экспортирует файлы из индекса Git во временную папку. Он устанавливает зависимости из локального кеша npm по lock-файлу индекса и запускает там `npm run check`. Если пакета нет в кеше, выполните `npm ci` для lock-файла, который собираетесь добавить в индекс. Git также проверяет заголовок коммита. CI запускает те же локальные проверки и сверяет lock-файл с базой уведомлений npm. [Справочник по качеству](../reference/quality.md)

## Имена коммитов

Используйте короткий заголовок на английском с глаголом в повелительном наклонении. Формат — `<type>(optional-scope)[!]: <summary>`. Длина заголовка должна быть не более 72 символов. Область указывайте в нижнем регистре, разделяя слова дефисами.

| Тип | Назначение |
| --- | --- |
| `feat`, `fix` | Пользовательская возможность или исправление поведения либо совместимости |
| `docs`, `test` | Только документация или только тесты |
| `refactor`, `perf` | Внутренняя структура или измеренное быстродействие |
| `build`, `ci`, `chore` | Инструменты, автоматизация или обслуживание |

```text
feat(core): read a saved snapshot
fix(html)!: reject unsupported link schemes
docs(contracts): explain diagnostic references
test(guards): cover a forbidden import
chore(release): prepare v0.1.0
```

Делайте одно изменение на коммит. Отмечайте несовместимое изменение знаком `!` или отдельной строкой `BREAKING CHANGE:` в конце сообщения. Используйте `chore(release): prepare vX.Y.Z ...` для релиза, обновления версии или метаданных релиза.
