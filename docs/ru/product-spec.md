# Продуктовая спецификация

[English version](../product-spec.md)

Спецификация описывает запланированную поддержку.

## Пользователи и результат

- Разработчик компилирует дизайн в исходники и собирает результат в чистом проекте. Повторный импорт позволяет увидеть изменения файлов.
- Команда дизайн-системы сопоставляет токены и компоненты со своим каталогом. Она получает UI-кит с объявленными вариантами и отчёты об отсутствующих привязках.
- Агент использует один контракт через CLI или MCP. Он читает стабильные ID диагностики и предлагает решения для согласования. Интеграция агента устанавливается отдельно от ядра.

Сравнивайте AIK с действующими инструментами на одинаковых макетах. Измеряйте качество вывода, ручную работу и воспроизводимость.

## Профили и цели

| Профиль | Вывод | Первый запланированный релиз |
| --- | --- | --- |
| `site` | Семантические страницы, CSS, локальные ассеты и объявленные ссылки | 0.1 · HTML/CSS |
| `ui` | Экран или компонент с объявленными свойствами, слотами и ID событий. Хост подключает данные и эффекты | 0.2 · React и TypeScript |
| `kit` | Токены, темы, контракты компонентов, варианты и примеры. Привязка цели добавляет исходники компонентов | 0.2 · React, TypeScript и DTCG |

Выбирайте цель, профиль и настройки отдельно. HTML/CSS — цель. BEM — соглашение об именах CSS. JavaScript или TypeScript используется для поведения и интеграций при необходимости. Матрица поддержки перечисляет допустимые сочетания.

| Вход или выход | Запланированная поддержка |
| --- | --- |
| Дизайн с деревом слоёв | Снимок выделения Figma в 0.1. Sketch и Penpot в 0.3 |
| Неструктурированный вход | Пользовательская история и PNG в 0.4. Модель предлагает правила для согласования |
| Веб-вывод | HTML/CSS и BEM в 0.1. React и TypeScript в 0.2. Vue, Angular, Web Components и варианты JS/TS по цели в 0.6 |
| Мобильный вывод | React Native в 0.5. SwiftUI и Jetpack Compose в 0.7 |
| Обмен дизайном | Токены DTCG в 0.2. Редактируемый экспорт Figma и маршрут SVG в 0.8 |
| Интерфейсы агентов | Версионированный JSON CLI в 0.1. MCP и устанавливаемые адаптеры агентских инструментов в 0.4 |

Проверьте совместимость перед добавлением формата. Порядок зависит от подтверждённых возможностей редакторов и SDK.

## Поведение

- Один поддерживаемый снимок, разрешённые привязки, профиль и lock-файл должны давать одинаковые файлы и машинную диагностику для одного запроса.
- При неоднозначном замысле пользователь задаёт правило или принимает предложение. Элемент с текстом **Купить** может вести на страницу или отправлять форму. Строгая сборка должна указать отсутствующее действие у этого узла.
- Политика `strict` по умолчанию должна остановить сборку при неподдержанной обязательной возможности. Пользователь может включить `best-effort` и разрешить конкретные коды диагностики. Декоративная иллюстрация может стать локальным ассетом, если компилятор сообщает о потере редактируемости. Обе политики должны остановить сборку при потере обязательной семантики, взаимодействия или доступности.
- Адаптивный вывод должен учитывать наблюдаемую компоновку, объявленные варианты, брейкпоинты и поддержанные ограничения. Дерево задаёт порядок чтения. Проверяйте длинный текст и реальное масштабирование.
- Первый продукт использует локальный CLI и плагины. Хосты связывают события и данные. Вывод бизнес-логики, генерация backend, облачная публикация, редактирование файлов с ручными правками и двусторонняя синхронизация находятся за рамками текущих черновиков.

## Проверки реализуемости

| Решение | Доказательство перед заморозкой |
| --- | --- |
| Захват Figma через Plugin API | Экспортировать два связанных тестовых фрейма. Зафиксировать область, Auto Layout, ассеты и ссылки на источник. Указать недоступные элементы библиотек |
| Правила Figma → HTML | Задать порядок чтения и навигацию без повторного описания геометрии. Проверить адаптивность и доступность по двум независимым референсам |
| Один офлайн-компилятор для агентских инструментов | Передать один запрос с lock-файлом через CLI и MCP. Сравнить файлы, диагностику и повторный запуск |
| Sketch, Penpot и редактируемый экспорт | Зафиксировать реальную версию формата и область доступа. Проверить неподдержанную структуру |
| UI-кит и мобильный вывод | Собрать пакет в чистом приложении. Проверить поведение. Запустить мобильный вывод на объявленном SDK и симуляторе |

Перед заморозкой подтвердите корпус пилота, права на ассеты и шрифты, целевые приложения, версии SDK и бюджет выполнения.
