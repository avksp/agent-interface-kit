## Диагностика v1

| Поле | Требование |
| --- | --- |
| `code` | Должно быть стабильным машинным кодом. Первая — прописная буква ASCII. Используйте прописные буквы ASCII, цифры и одиночное подчёркивание между группами. Пример — `MISSING_ACTION` |
| `severity` | Должно быть `info`, `warning` или `error` |
| `sourceRef` | Должно быть непустой ссылкой на источник или `null`, если места в источнике нет |
| `feature` | Может указывать возможность непустой строкой |
| `fallback` | Может указывать разрешённую замену непустой строкой |

Клиент должен использовать `code` для программных решений. Для показа места, где нужно действие пользователя, следует использовать `sourceRef`. Например, если у узла Figma отсутствует действие, компилятор сообщает `MISSING_ACTION` и ссылку на узел.

## Манифест артефактов v1

Модуль записи должен вывести `schemaVersion` со значением `aik-artifact-manifest.v1` и массив `files`. Запись каждого файла должна содержать следующие поля.

| Поле | Требование |
| --- | --- |
| `path` | Относительный путь с разделителем `/`. Схема отклоняет пустые, абсолютные пути, пути с буквой диска и сегментами из точек. Она также отклоняет обратные слеши, управляющие символы и путь самого корневого манифеста |
| `mediaType` | Медиатип в нижнем регистре без параметров, например `text/html` |
| `sha256` | SHA-256 байтов файла в нижнем регистре шестнадцатеричной записи, 64 символа |

Пример указывает SHA-256 байтов UTF-8 строки `<main>Example</main>` с LF в конце. Модуль записи также должен проверить нахождение путей в папке вывода, коллизии после нормализации, стабильный порядок и хеш каждого файла. Для этих проверок нужны папка вывода и байты файлов. [Архитектура](../architecture.md)
