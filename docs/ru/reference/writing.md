# Справочник по документации

[English version](../../reference/writing.md)

## Язык

Английский — основной язык. У каждого руководства для людей должен быть русский перевод. Используйте английский для `README.md`, `AGENTS.md`, навыков и файлов, по которым агенты выполняют или проверяют работу. Русские переводы для людей храните в `ru/`. Обновляйте обе версии в одном изменении. Сохраняйте команды, пути, идентификаторы, примеры кода, единицы, пороги и силу требований.

## Короткий технический английский

Ориентируйтесь на эти правила Simplified Technical English (STE). Пишите короткими предложениями в активном залоге. Указывайте исполнителя и используйте один термин для одного понятия. В процедурах давайте одно действие на шаг. Указывайте условие перед действием. Явно описывайте исключения и условия отказа. [Обзор ASD-STE100](https://asd-ste100.org/about.html)

Проверяйте объяснение методом Фейнмана. Объясните термин простыми словами. Приведите конкретный пример. Если для примера нужен непонятный термин, объясните его или упростите пример. Например, снимок — сохранённая копия входа. При открытии одного снимка компилятор получает те же байты дизайна.

## Обозначения требований

Используйте английские прописные термины в нормативных положениях. Толкуйте их по BCP 14. В обычном тексте используйте строчные слова. [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) · [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174)

| Термин | Значение |
| --- | --- |
| MUST, MUST NOT | Требование или запрет |
| SHOULD, SHOULD NOT | Рекомендация по умолчанию. Перед исключением нужно понять и оценить последствия |
| MAY | Разрешённый вариант |

Укажите исполнителя, условие, действие и наблюдаемую проверку. Например, если в JSON нет поля `sourceRef`, валидатор диагностики должен отклонить запись. Тест пропускает поле и проверяет отказ. [Схема диагностики](../../../schemas/diagnostic.v1.schema.json)

## Виды документов

Выбирайте вид документа по цели читателя. У каждого вида своя задача. [Diátaxis](https://diataxis.fr/)

| Вид | Назначение | Место в AIK |
| --- | --- | --- |
| Объяснение | Понять, почему дизайн системы устроен так | `docs/ru/architecture.md` |
| Справочник | Найти поле, правило или интерфейс | `docs/ru/reference/` |
| Практическое руководство | Выполнить задачу с наблюдаемым результатом | `docs/ru/how-to/` |
| Учебник | Пройти учебный пример от начала до конца | Добавить, когда появится запускаемый пример |

## Машиночитаемые контракты

Для версионированного формата JSON опишите схему, смысл полей и правила, которые проверяются при выполнении. Определяйте структуру в JSON Schema Draft 2020-12. Проверьте допустимый пример и подходящий недопустимый случай. Для файлов ALK используйте схемы самого ALK. [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12) · [Контракты AIK](contracts.md)
