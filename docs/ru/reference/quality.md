# Качество кода и автоматические проверки

[English version](../../reference/quality.md)

## Правила проектирования

- Применяйте SOLID на реальных границах. Держите код, который меняется по одной причине, в одном модуле. Вводите интерфейсы в реальных точках замены. Реализация интерфейса должна сохранять заявленное поведение. Потребителю следует зависеть только от используемых операций. Соединяйте реализации на границе хоста.
- Применяйте DRY при одинаковых правилах и причинах изменения. Следуйте KISS и предпочитайте прямой поток выполнения и имеющийся API. Применяйте YAGNI и добавляйте абстракцию, когда она нужна для текущего требования.
- Используйте строгий TypeScript и ESM. Для встроенных модулей Node.js используйте `node:`. На границе доверия считайте входные значения неизвестными. Проверяйте их перед использованием. Избегайте небезопасных утверждений типов, необработанных промисов и скрытого состояния процесса. Возвращайте явные ошибки и освобождайте ресурсы при сбое.
- Измеряйте быстродействие в закреплённой среде. Оптимизация должна сохранять архитектуру, защитные меры и наблюдаемое поведение.

## Границы импортов

| Исходный слой | Допустимые зависимости внутри проекта |
| --- | --- |
| `design-tokens` | Свои модули и общие контракты |
| `compile-core` | Свои модули, общие контракты и логика токенов. Модуль записи находится в отдельной подпапке `src/writer/` |
| Плагины источников | API ядра, логика токенов и общие контракты. Редактор и сеть находятся на границе захвата |
| Правила преобразования для веба | API ядра, логика токенов и общие контракты |
| Плагины вывода | API ядра, логика токенов, общие контракты и применимые правила преобразования |
| CLI, MCP, интеграция ИИ и хосты редакторов | Соединяют нижние слои через публичные интерфейсы |

Проверка зависимостей проверяет статически разрешимые импорты, импорты типов и реэкспорты. Она отклоняет циклы, неразрешённые и обратные зависимости, импорты между плагинами и импорты инструментов или тестов из продукта. Для API между пакетами используйте их публичные exports.

## Правила безопасности

- Чистые стадии должны работать офлайн. Запись выполняет модуль записи. Доступ к редактору, сети и процессам остаётся в хостах. Значения, влияющие на воспроизводимость, передавайте явно.
- Обрабатывайте дизайн, архивы, предложения моделей и метаданные плагинов как данные. Проверяйте схему, ограничения размера и глубины и хеши ассетов. Экранируйте вывод для его контекста. Проверяйте схему URL и допустимость формата ассетов перед выводом. Модуль записи должен проверить разрешённые пути, символьные ссылки, коллизии и прежний результат перед публикацией.
- Не помещайте секреты в отслеживаемые файлы, диагностику и доказательства. Для проверенного процесса хоста передавайте явные аргументы. Избегайте shell для недоверенных данных. При установке зависимостей скрипты жизненного цикла по умолчанию отключены. Проверяйте закреплённое дерево зависимостей.
- Объясняйте точечные исключения линтера с указанием причины и доказательства ревью. Если проверка не прошла, устраните нарушение или проверьте предлагаемое изменение правила.

| Проверка | Команда | Наблюдаемый результат |
| --- | --- | --- |
| TypeScript и линтер с типами | `npm run typecheck`, `npm run lint` | Отказ при некорректном коде, небезопасном использовании типов или выбранных опасных API |
| Архитектура | `npm run guard:architecture` | Отказ при запрещённой или неразрешённой зависимости |
| Безопасность | `npm run guard:security` | Отказ при запрещённой зависимости или приватном пути в индексе Git |
| Зависимости | `npm run audit:deps` | Отказ при известных уязвимостях уровня high или critical в закреплённом дереве |
| Локальные проверки | `npm run check` | Проверка типов, линтер, импорты, индекс и тесты |

Статические проверки покрывают настроенные шаблоны. Для поведения редактора, границ файловой системы, активного содержимого и параллельного выполнения нужны соответствующие негативные и интеграционные тесты. [Приёмка](../verification.md)
